# 🏗️ KaloriiAI — Архитектурные решения

> Документ описывает ключевые архитектурные решения и причины их принятия.
> Обновляй этот файл при каждом значимом архитектурном изменении.

## Решения и обоснования

### 1. SQLite вместо PostgreSQL
- **Почему:** На сервере уже есть PostgreSQL для других сервисов. SQLite изолирован, не конфликтует, легко бэкапится (один файл). Для 1-3 пользователей производительности более чем достаточно.
- **Компромисс:** Нет concurrent writes (не проблема при 1-3 юзерах). Используем `aiosqlite` для async доступа.
- **Файл БД:** `backend/data/db.sqlite3`

### 2. React + TypeScript (а не Vue/Svelte)
- **Почему:** Лучшая поддержка Capacitor для будущей упаковки в Android APK. Огромная экосистема. TypeScript для надёжности типов.
- **Альтернативы:** Vue + Capacitor тоже работает, но React лучше поддерживается в Capacitor-экосистеме.

### 3. Vite (а не Webpack/CRA)
- **Почему:** Молниеносная сборка и HMR. Нативная поддержка TypeScript. Отличная интеграция с React и Tailwind.

### 4. Tailwind CSS (а не CSS Modules / styled-components)
- **Почему:** Быстрая стилизация тёмной темы. Утилитарный подход идеален для компактного проекта. Mobile-first из коробки. Не нужно переключаться между файлами.

### 5. Zustand (а не Redux / MobX / Context)
- **Почему:** Минимальный бойлерплейт, простой API. Для приложения такого размера Redux избыточен. Context API плох для частых обновлений (ре-рендеры).

### 6. FastAPI (а не Django / Flask / Express)
- **Почему:** Async Python из коробки. Автодокументация API (Swagger). Отличная работа с файлами (multipart uploads). Pydantic для валидации. Быстрый.

### 7. JWT (а не сессии)
- **Почему:** Stateless аутентификация. Хорошо работает с SPA и будущим мобильным приложением. Access + Refresh токены для безопасности.

### 8. Мультипровайдер AI с fallback
- **Почему:** Бесплатные модели часто недоступны из-за rate limits. Цепочка из 6+ моделей повышает надёжность. Gemini 3.8 Flash — основная (лучшее качество), дальше fallback по убыванию.
- **Логика retry:** 2 попытки на провайдера, 5 сек задержка между попытками, затем переход к следующему.

### 9. Без Docker для KaloriiAI
- **Почему:** Сервер и так нагружен Docker-контейнерами VPN. KaloriiAI — простой Python + статика, достаточно systemd.

### 10. Порт 5100
- **Почему:** Далеко от стандартных портов, не конфликтует с VPN сервисами на сервере (2053, 2222, 8443, 39851). Бэкенд слушает только на localhost, наружу через Caddy.

### 11. Caddy (а не Nginx)
- **Почему:** Автоматический TLS через ACME. Простой конфиг. Уже установлен на сервере.

### 12. Recharts (а не Chart.js / D3)
- **Почему:** React-нативные компоненты (не canvas-обёртки). Красивые анимации из коробки. Адаптивные графики. Простой API.

## Схема взаимодействия компонентов

```
Browser/PWA
    ↓ HTTPS
Cloudflare DNS (kalorii.lopni.fun)
    ↓
Caddy (port 443)
    ├── /api/* → reverse_proxy → FastAPI (127.0.0.1:5100)
    │                               ├── SQLite (data/db.sqlite3)
    │                               ├── Uploads (uploads/)
    │                               └── AI Providers
    │                                   ├── Gemini API (httpx)
    │                                   └── OpenRouter (httpx)
    └── /* → static files → React build (/var/www/kalorii)
```

## Безопасность

| Аспект | Реализация |
|---|---|
| Пароли | bcrypt хеширование |
| Аутентификация | JWT access + refresh tokens |
| HTTPS | Caddy автоматический TLS |
| API ключи | .env файл, не в коде |
| Загрузка файлов | Валидация MIME (image/*), макс 10MB, сжатие через Pillow |
| CORS | Только разрешённые домены |
| Rate limiting | AI эндпоинт: 10 req/min на пользователя |
