## 2. Глубокое обновление системных промптов, парсеров и валидаций AI

### Проблема:
Системные промпты долгое время не актуализировались:
1. Крупы, макароны и мясо часто оценивались как сырой продукт, из-за чего калорийность порции каши или гарнира завышалась в 2.5–3 раза.
2. Не было строгой таблицы бытовых мер (вес куска хлеба, яйца, ложки масла, фруктов), что приводило к галлюцинациям в граммовках.
3. При сканировании этикеток происходила путаница между «КБЖУ на 100 г» и «КБЖУ всей упаковки».
4. При нажатии «Пересчитать через AI» без фото стирался контекст предыдущего веса и ингредиентов (команды «съел половину» или «без майонеза» не могли пересчитать исходное блюдо).
5. В голосовых сообщениях самоисправления пользователя («двести... ой, сто пятьдесят грамм») не всегда корректно учитывались.

### Реализованное решение ([`backend/app/utils/ai_providers/base.py`](file:///c:/Fvus/some/KALORII/backend/app/utils/ai_providers/base.py)):

#### 2.1. Правило «Готовый продукт по умолчанию»:
- Во всех промптах (`build_system_prompt`, `build_text_prompt`, `build_voice_prompt`, `build_meal_plan_prompt`) закреплено строгое правило:
  - Все крупы (гречка, рис, овсянка, булгур, киноа), макароны/паста, бобовые, мясо, птица и рыба оцениваются **по умолчанию в готовом (отварном/приготовленном) виде**, если пользователь явно не написал «в сухом виде» или «сырой фарш».
  - Коэффициенты разваривания круп учтены в системной инструкции (100 г готовой гречки ~ 110-120 ккал, а не 330 ккал сухой крупы).

#### 2.2. Таблица бытовых мер и скрытых жиров:
- В промпты внедрены эталонные бытовые ориентиры:
  - 1 куриное яйцо C1 ~ 50–55 г (70–75 ккал, 6г Б, 5г Ж, 0.5г У).
  - 1 кусок хлеба / тост ~ 30–35 г (75–85 ккал).
  - 1 столовая ложка растительного масла ~ 12–14 г (110–120 ккал, ~12г Ж).
  - 1 чайная ложка масла ~ 5 г (45 ккал).
  - 1 столовая ложка сметаны 15-20% ~ 20–25 г (40–50 ккал).
  - 1 средний банан (без кожуры) ~ 110–130 г (105–120 ккал).
  - 1 среднее яблоко ~ 150–180 г (75–90 ккал).
  - Капучино/латте ~ 200–300 мл с учётом калорийности цельного молока.
- Обязательный учёт скрытых жиров при жарке (минимум +5–10 г масла) и заправках салатов.

#### 2.3. Разделение режимов этикеток и каталога:
- При сканировании этикетки в каталог продуктов ([`backend/app/routers/barcode.py`](file:///c:/Fvus/some/KALORII/backend/app/routers/barcode.py)):
  - Модель возвращает КБЖУ строго **на 100 г продукта**, а массу нетто упаковки помещает в `weight_grams`.
  - В схему [`backend/app/schemas/ai.py`](file:///c:/Fvus/some/KALORII/backend/app/schemas/ai.py) добавлены поля `brand` и `barcode`, извлекаемые напрямую через AI OCR.
- При обычном распознавании скриншота доставки или тарелки:
  - Модель пересчитывает КБЖУ на всю съеденную порцию целиком.

#### 2.4. Сохранение полного контекста при пересчёте (`/recalculate`):
- В [`backend/app/routers/meals.py`](file:///c:/Fvus/some/KALORII/backend/app/routers/meals.py) в метод `recalculate_meal` передаётся расширенный контекст:
  - Текущее название блюда, его текущий вес (`weight_grams`), список ингредиентов с граммами и КБЖУ каждого компонента.
  - Благодаря этому уточнения вроде: *«съел только половину»*, *«убери сырный соус»*, *«добавил ещё 50 г риса»* или *«замени свинину на курицу»* точно модифицируют существующее блюдо, сохраняя остальные компоненты.

#### 2.5. Обработка самоисправлений в голосе:
- В `build_voice_prompt` закреплено правило для транскрибирования аудио:
  - Если пользователь в процессе речи исправил вес или продукт (*«съел двести... а нет, грамм сто двадцать творога»*), модель берёт в расчёт только **финальное скорректированное значение**, а текст очищает от слов-паразитов.

#### 2.6. Нормализация слотов и валидация Этуотера:
- В генераторе рационов [`backend/app/routers/meal_plan.py`](file:///c:/Fvus/some/KALORII/backend/app/routers/meal_plan.py) добавлена функция `_normalize_meal_label`, которая приводит слоты к каноническим: `Завтрак`, `Обед`, `Ужин`, `Перекус` (для корректной группировки по времени в дневнике).
- Ингредиенты генерируются в именительном падеже единственного числа для удобной группировки в Списке покупок.
- В `parse_food_result` и `parse_meal_plan_result` внедрена покомпонентная проверка формулы Этуотера:
  $$\text{Калории} \approx 4 \times \text{Белки} + 9 \times \text{Жиры} + 4 \times \text{Углеводы}$$
  с автоматической балансировкой отклонений для каждого ингредиента и блюда в целом.

## 3. Умное отображение карточки обновления в профиле

### Проблема:
В мобильном приложении Android на странице «Профиль» снизу постоянно висела большая плашка «Приложение KaloriiAI для Android — Скачать приложение». Это сбивало пользователей с толку, поскольку они уже находились внутри установленного приложения.

### Реализованное решение:
В [`frontend/src/pages/ProfilePage.tsx`](file:///c:/Fvus/some/KALORII/frontend/src/pages/ProfilePage.tsx) логика рендеринга карточки изменена на строго контекстную:
```tsx
{(!isNativeApp() || hasAppUpdate) && (
  <div className="bg-gradient-to-r ...">
    ...
    <h3 className="text-sm font-bold text-white my-0">
      {isNativeApp() ? 'Обновление KaloriiAI для Android' : 'Приложение KaloriiAI для Android'}
    </h3>
    <span className="...">v{serverVersion}</span>
    {hasAppUpdate && (
      <span className="... bg-amber-500/20 text-amber-300 ...">
        Доступно обновление
      </span>
    )}
    <p className="text-xs text-neutral-400 mt-1 my-0">
      {isNativeApp()
        ? `Доступна новая версия v${serverVersion}. Обновите приложение для доступа к новым функциям и улучшениям.`
        : 'Скачайте последнюю версию приложения (APK) — мгновенный запуск, камера и синхронизация с вашим аккаунтом'}
    </p>
    <button onClick={() => downloadLatestApk(serverVersion)}>
      <Download className="w-4 h-4" />
      <span>{isNativeApp() || hasAppUpdate ? 'Скачать обновление' : 'Скачать приложение'}</span>
    </button>
  </div>
)}
```

**Поведение:**
1. **Внутри мобильного приложения (`isNativeApp() === true`):**
   - Если установлена актуальная версия (`hasAppUpdate === false`), баннер **полностью скрыт**.
   - Если на сервере вышла новая версия (`hasAppUpdate === true`), баннер **появляется** с текстом об обновлении и кнопкой «Скачать обновление».
2. **На веб-сайте (`isNativeApp() === false`):**
   - Баннер **отображается всегда**, позволяя посетителям сайта скачать Android APK.

## 4. Конвейер автообновления и быстрый сборщик APK (Zero-Docker)

### 4.1. Как работает система уведомлений об обновлениях:
1. Эндпоинт `GET /api/health` возвращает:
   ```json
   {
     "status": "ok",
     "app": "KaloriiAI",
     "version": "1.5.4",
     "apk_version": "1.5.4",
     "apk_url": "/kalorii-ai.apk?v=1.5.4"
   }
   ```
2. Клиент при старте и при каждом возвращении из фона (`visibilitychange` / `window.onfocus`) вызывает `checkServerAppVersion()`:
   - Сравнивает серверную версию с локальной константой `APP_VERSION` через `compareAppVersions(remote, local)`.
   - Если `remote > local`:
     - В [`Layout.tsx`](file:///c:/Fvus/some/KALORII/frontend/src/components/layout/Layout.tsx) плавно выезжает верхний глобальный баннер **«Доступно обновление v1.5.4 — Скачайте новую версию приложения KaloriiAI»** с кнопкой **«Скачать»** и кнопкой закрытия.
     - В [`ProfilePage.tsx`](file:///c:/Fvus/some/KALORII/frontend/src/pages/ProfilePage.tsx) активируется блок обновления.
     - Нажатие на «Скачать» открывает ссылку `https://kalorii.lopni.fun/kalorii-ai.apk?v=1.5.4`, передавая загрузку системному загрузчику Android.

### 4.2. Скрипт сборки и подписи APK без Docker ([`scripts/update_apk_web_assets.py`](file:///c:/Fvus/some/KALORII/scripts/update_apk_web_assets.py)):
Не требует работающего Docker Desktop. Работает локально через Python + Java:
1. Заменяет `assets/public/*` внутри существующего базового APK свежими файлами из `frontend/android/app/src/main/assets/public/` (собранными через `npm run build:sync-static` и `npx cap sync android`).
2. Обеспечивает строгое выравнивание ZIP-записей (`zipalign -p 4`):
   - Файлы `.so` выравниваются по границе 4096 байт.
   - Текстовые и графические ассеты выравниваются по границе 4 байт.
3. Подписывает APK официальным релизным ключом `kalorii-release-key.jks` через `scripts/tools/apksigner.jar` по схемам **v1 + v2 + v3**.
4. Проверяет цифровую подпись (`apksigner verify --verbose`).
5. Копирует готовый APK в корень `kalorii-ai.apk` и в папку сервера `backend/static/kalorii-ai.apk`.

## 5. Инструкция по сборке, деплою и выпуску релизов для будущих ИИ-агентов

Если нужно выпустить новую версию приложения (например, `v1.5.5`), следуй строго этому протоколу:

### Шаг 1: Повышение версии в 4 файлах:
1. [`frontend/src/utils/platform.ts`](file:///c:/Fvus/some/KALORII/frontend/src/utils/platform.ts) -> `export const APP_VERSION = '1.5.5'`
2. [`backend/app/main.py`](file:///c:/Fvus/some/KALORII/backend/app/main.py) -> `APP_VERSION = "1.5.5"`
3. [`frontend/android/app/build.gradle`](file:///c:/Fvus/some/KALORII/frontend/android/app/build.gradle) -> `versionCode 5`, `versionName "1.5.5"`
4. [`frontend/package.json`](file:///c:/Fvus/some/KALORII/frontend/package.json) -> `"version": "1.5.5"`

### Шаг 2: Сборка фронтенда и синхронизация Capacitor:
```powershell
cd frontend
npm run build:sync-static
npx cap sync android
cd ..
```

### Шаг 3: Сборка и подпись Android APK:
```powershell
.\backend\.venv\Scripts\python.exe scripts/update_apk_web_assets.py
```
*(Проверь вывод: должно быть `Verifies: true`, схемы `v2: true`, `v3: true`).*

### Шаг 4: Тесты:
```powershell
cd frontend; npm run test; cd ..
cd backend; .\.venv\Scripts\python.exe -m pytest; cd ..
```

### Шаг 5: Коммит и пуш в ветку `main`:
```powershell
git add -A
git commit -m "feat(release): v1.5.5 - ..."
git push origin main
```

### Шаг 6: Деплой на продакшен-сервер (Швеция, `62.60.186.12`):
```powershell
ssh -o StrictHostKeyChecking=no -J fi root@62.60.186.12 "cd /opt/kalorii && git pull origin main && docker compose -f docker-compose.prod.yml up -d --build"
```

### Шаг 7: Верификация продакшена:
```powershell
ssh -o StrictHostKeyChecking=no -J fi root@62.60.186.12 "curl -s http://127.0.0.1:5100/api/health && curl -I https://kalorii.lopni.fun/kalorii-ai.apk?v=1.5.5"
```

Должен вернуть версию `1.5.5` и HTTP `200 OK` для скачивания APK. После этого у всех мобильных пользователей моментально всплывёт баннер обновления.
